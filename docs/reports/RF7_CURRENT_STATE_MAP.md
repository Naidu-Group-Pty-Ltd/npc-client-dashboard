## 3. Renderers — four engines where the target is one

1. **`weasyprint-service/` container** (pdf/ua-1) — the programme's renderer:
   the ten migrated formats and `render-template-pdf`, behind the network
   isolation gate (`RENDER_BOUNDARY.md`) and `compileTemplateHtmlForPdf`.
2. **The legacy investment compiler** — `render-investment-report-pdf`'s
   fallback HTML path into the same container; by design while design-system
   coverage is 0.14% (`COVERAGE.md`), and the reason a refused template render
   still produces a well-typeset document.
3. **pdf-lib on the server** — `quantitative-report-pipeline` draws its PDF
   itself (`REPORT_VERSION = 1` local constant, own bucket, own `money()`
   formatter).
4. **pdf-lib in the browser** — `PixelPerfectPDFGenerator.tsx` (wrapped by
   `ClientPDFGenerator.tsx`, which calls `reconcileStoredFinancials` client
   side), mounted from `InvestmentReportViewer`, the export panel and
   `ClientPropertyInvestmentReport`.

Shared drawing primitives that must stay single: `markdown.pure.ts` (the only
Markdown renderer, escape-first), `vizDirectives`/`vizFigures` (chart
vocabulary), `packMarkdownPages` (paging shared by block and projection).

## 7. Report fact ownership — what is canonical today

**Property facts** (address, price, rent, type, beds/baths/cars, land, build):
`composePropertySpecs` (`propertyRecord.pure.ts`) normalises the record;
`normalisePropertyType` resolves the two type vocabularies (S1-D);
bedroom/bathroom default fabrication was removed (closing pass). The report's
address is `investment_reports.property_address` (listings-side composition
rules are `ADDRESS_COMPOSITION.md` and do not flow here).

**Financial facts** (annual rent, gross/net yield, expenses, cash flow, loan,
deposit, holding cost, stamp duty, LVR, projections):
`propertyMetrics.pure.ts` is the one definition per figure with the basis
carried (`DERIVED_FIGURES.md`); `rentalEvidence.pure.ts` is the one rent;
`reconcileStoredFinancials` + `healFinanceIdentity` heal the 21 contradictory
stored rows **on read** for every reader — caller list re-verified this pass:
`render-investment-report-pdf`, `get-investment-reports`, both comparison
functions, `cashFlowProjection`, `reportBindingProjection`,
`investment/normalise`, `financialChapters`, `financialEngine`,
`sectionRegistry`, and (browser) `ClientPDFGenerator`. Stamp duty:
`_shared/stampDuty/` and nowhere else.

**Market facts** (suburb, geography, demographics, growth, vacancy, demand,
employment, transport, comparables, provenance): the ingested real registers
(ABS census/SEIFA/ERP, crime ×4 states, climate, GTFS transport, RBA macro,
zoning) reach prose only through the deterministic prompt-block modules
(`censusPromptBlocks`, `planningStatBlocks`, `crimeStatBlocks`,
`climateStatBlocks`, `macroEconomicBlock`, `regionalTrendBlocks` — import list
on the generator verified this pass). Market **evidence with provenance** in
the V2 sense exists only in `marketEvidence.pure.ts` (shadow side).

**Scoring facts**: V1 `investment_score` Json on the row (§9). V2:
`scoreOutputContract` — the object Reporting must eventually consume, and the
only shape that carries versions, coverage, eligibility and provenance.

**Verdict**: per-figure canonicality is genuinely achieved for financials and
market registers; what does not exist is **one typed Report Fact Contract** —
each pipeline assembles the same pure modules into its own untyped bundle
(`propertyDetails` / projection rows / prompt blocks), which is where silent
divergence re-enters. That contract is the first build item (§19–§21).

## 8. Calculation ownership — deterministic vs model (the five classes)

Class 1 (deterministic fact) and class 2 (deterministic calculation):
`financialEngine`, `cashFlowProjection`, `propertyMetrics`, `stampDuty`,
borrowing-capacity engine, `capRateEngine`/`dcfEngine` (units differ by
design — ratio vs percentage, pinned), `measure.pure`. Class 3 (scoring
output): §9. Class 4 (sourced market evidence): the registers above. Class 5
(narrative): §10.

Enforcement that a model computes nothing authoritative: `factReconciliation`
(tolerances: yields ±0.25 pt absolute, LVR ±0.5; verb-introduction refused),
the verdict-sentence guard (P1-D), Portfolio's deterministic-fields-assembled-
after-the-model rule (PF-4), Commercial's numeric-free tool schema, the rent
prohibition with a permitted qualitative alternative, and the honest-absence
rules per format ("absent is omitted, never a dash"). Where information is
unavailable the document says so; the fabrication class was closed in F-A/F-B
with a CI guard (F-C).

## 9. Score ownership

**V1 — the authoritative production score.** `investment-scoring-service`:
five dimensions (yield/growth/location/demand/risk) with weights, SWOT,
coverage machinery (min 3 dimensions for a headline). Computed at generation
and stored **unversioned** in `investment_reports.investment_score` (no
version field on its interface — verified this pass); snapshotted into
`report_versions`. Readers: the scorecard/strengths blocks via
`reportBindingProjection`, the due-diligence scorer (P1-C), comparisons
(historic rows normalised by `migrate-comparison-scores`), briefings (score
fallback on fork fixed, P1-C). `backfill-investment-scores` exists for the
column. A `risk-assessment-service` is called by
`regenerate-report-qualitative` (V1-adjacent; one look owed in RF-7.1).

**V1 defects found by this pass, recorded not fixed** (§13 for the decision):
its intake transform (`transformInputData`, `investment-scoring-service/
index.ts` ~72–115) defaults `propertyType || 'house'`, `walkScore || 0`,
`schoolsNearby || 0`, `propertyPrice || 0`, and collapses **falsy measured
values to undefined** (`priceGrowth1Year || undefined`, `vacancyRate ||
undefined` — a genuine 0 reads as no data). Buyer LVR and cash flow are inputs
to its Risk. These are exactly the classes Scoring V2 removes.

**V2 — frozen shadow.** `scoreInvestmentV2Shadow` (2.1.0-shadow) →
`buildScoreOutput` (1.0.0). Unwired, CI-asserted; this pass re-swept the repo:
no edge entrypoint imports anything under `_shared/reports/market` or `/risk`,
and the only non-test `src` consumer of the bridges is the probe diagnostics
panel. Reporting must never recreate dimension scores, composite, grade,
eligibility, caps, weights or methodology — it reads the contract.

## 11. Template / white-label ownership

Selection: `reportTemplateSelection.pure.ts` (per user+format, read before
ranking, `unavailable` never silently substituted; the alias map is single).
Catalogue: 43 voice + 500 family masters, generated never hand-written;
colourways are tokens only, with block geometry byte-identical across a
family's ten palettes (spec-pinned). Brand: `brand_snapshot_id` pins the brand
snapshot on the row; `organisationProjection` produces `org.*`; the converter
resolves palettes and never stores them.

**Does the separation hold?** Structurally yes: templates bind projection
paths; blocks compute nothing; `PRODUCTION_SAFE_BLOCK_TYPES` refuses
HTML-accepting blocks; the markdown block is escape-first; catalogue specs
assert masters bind only what the projection publishes. The known residual
hazard is that **an unresolved binding renders as the empty string** — a
template cannot alter a fact, but it can silently omit one; the check that
catches the class is resolving every bound path against a verbatim production
row. The fact contract (§19) is where "absent renders as a stated absence, not
a blank" becomes enforceable once, rather than per format.

## 16. Versioning — what a stored report can and cannot explain

Can explain today: its content version (`current_version` +
`report_versions.version_number` with changelog and full data-block snapshot),
its generation engine and lineage, its brand snapshot, its generation
timestamps, its calculation version **when the generator wrote it**
(`calculation_version` is written only by `generate-investment-report`;
nullable elsewhere).

Cannot explain today: **which scoring methodology produced its score** (V1
score JSON is unversioned — the V2 contract fixes this by construction);
**which template and template version drew its PDF** (ledger has template_id
but no report link column; the row has only `pdf_url`); **which narrative
prompt/registry version wrote its prose** (the registry is code-versioned
only); the quantitative pipeline's `REPORT_VERSION = 1` is a local constant.
Gaps are build items RF-7.3.

## 17. Cross-report consistency — contradiction/reconciliation matrix

| fact | same report | across reports of the same property | mechanism |
| --- | --- | --- | --- |
| price / rent / beds / baths / land / type | consistent (one projection per row) | can differ **legitimately** when the record changed between generations; `canonical_property_key` links rows | snapshot semantics; §18 target restated below |
| gross/net yield | one definition + basis | historic rows retain printed zeros (84/1,072) from the fixed cause | `propertyMetrics` + basis labels; stored bytes kept |
| LVR | basis-labelled | origination vs current coexist correctly | `DERIVED_FIGURES.md` |
| deposit/loan identity | healed on read everywhere (21 rows) | same | `healFinanceIdentity`, arbiter `keyMetrics.lvr` |
| score/grade | one stored score per row | briefing child fallback fixed; comparisons normalised | P1-C, `migrate-comparison-scores` |
| prose figures vs record | reconciled with absolute tolerances | flags on `validation_flags` | `factReconciliation` |

Target invariant (mandate): *same property + same snapshot + same methodology
version = same authoritative fact everywhere.* The remaining seams are the
untyped fact bundles (§7) and the unversioned score (§16); both close with the
fact contract + score contract, without touching stored bytes.

## 19. Target architecture, mapped onto what exists

```

→ CANONICAL FACT LAYER            — pure modules exist; ONE TYPED CONTRACT does not
→ DETERMINISTIC FINANCIALS        — financialEngine et al. (exist)
→ SCORING ENGINE                  — V1 live; V2 frozen shadow
→ CANONICAL SCORE OUTPUT CONTRACT — scoreOutputContract 1.0.0 (exists)
→ REPORT FACT CONTRACT            — TO BUILD (facts + calcs + score + provenance, versioned)

→ HTML / UI PREVIEW               — viewers (exist)
```

The deltas, in dependency order: (a) the Report Fact Contract; (b) version
stamps; (c) renderer consolidation; (d) composer unification per family;
(e) the dev-only score comparison. Nothing in the list requires — or permits —
Scoring V2 to become authoritative.
